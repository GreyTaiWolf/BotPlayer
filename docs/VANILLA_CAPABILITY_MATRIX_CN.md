# BotPlayer 原版能力矩阵

> 文档状态：验收基线 v1
>
> 更新日期：2026-07-26
>
> 适用游戏：Minecraft Java 1.21.1

“玩家会的 bot 也会”必须能被测试，不能只依赖演示或模型回答。本矩阵把原版玩法拆成能力
编号，规定首次实现、最迟验证、成功证据和当前状态。详细实现结构见
[ARCHITECTURE_AND_ROADMAP_CN.md](ARCHITECTURE_AND_ROADMAP_CN.md)。

## 成熟度

| 等级 | 含义 |
|---|---|
| `NONE` | 没有代码 |
| `KERNEL` | 只有玩家生命周期或底层入口 |
| `BASIC` | 固定场景能成功，没有完整恢复 |
| `RELIABLE` | 动态世界、取消、权限拒绝和常见失败可恢复 |
| `VERIFIED` | 自动测试、客户端验证和性能门槛均通过 |

当前除真实玩家生命周期外，动作能力均为 `NONE`。路线图写了任务不等于成熟度提升。

阶段门写成 `首次实现 → VERIFIED 截止`，例如 `P2 → P4` 表示 P2 建立基础能力，最迟在
P4 达到 `VERIFIED`；只写一个阶段表示首次实现和验证截止相同。P5A–P5D 是架构路线图中
的原版能力扩展子阶段。P10 只做硬化，不能成为任何 REQUIRED 能力的首次实现阶段。

本文件 A–L 中列出的所有能力 ID 默认都是 `REQUIRED_FOR_1_0`。没有写入矩阵的行为不能
被默认为已支持；明确不属于 1.0 的边界统一列在“OUT_OF_SCOPE”一节。

## 通用验收模板

每项能力必须记录：

1. 输入与调用者权限；
2. 必要观察和知识来源；
3. 前置物品、状态和环境；
4. 使用的动作与技能；
5. 成功后的真实世界证据；
6. 可取消点、超时和幂等规则；
7. 失败码、恢复策略和玩家说明；
8. 单元测试、GameTest、手工或 soak 证据；
9. 适用的 Minecraft/NeoForge/模组版本。

| C0 | 通过注册表、标签、配方和数据组件认识内容 |
| C1 | 使用标准方块、物品、实体和容器接口 |
| C2 | 使用管理员审核的声明式 Knowledge/Skill Pack |
| C3 | 使用版本绑定的 Java `BotModAdapter` |

每个适配项还要记录模组 ID、版本范围、环境指纹、菜单/技能版本和回归测试。未知自定义
菜单或隐藏机制默认询问或拒绝。

“外部技能库”指 JAR 外、服务器本地安装、管理员审核的数据包；不允许运行时从互联网
下载和执行模型生成代码。

## 发布门槛

| 节点 | 最低能力 |
|---|---|
| P2 退出里程碑（计划的 `0.1` alpha 完成构件） | LIFE 主路径 VERIFIED；基础 MOVE/ACT 达到 BASIC；安全背包 VERIFIED |
| `0.2.x alpha` | 基础生存、导航、采集、制作和战斗闭环达到 RELIABLE |
| `0.3.x beta` | 对话、受控 DeepSeek、记忆和至少一套模组 fixture 达到 RELIABLE |
| `0.4.x beta` | 多 bot 分工和锁达到 RELIABLE |
| `1.0.0` | A–L 的所有 `REQUIRED_FOR_1_0` ID 达到 VERIFIED；只有明确 OUT_OF_SCOPE 项可排除 |

`1.0.0` 不能仅凭“从空手做到铁工具”发布。至少还必须覆盖：

- 全套普通移动和生存；
- 方块、物品、容器和主要工作站；
- 农业、动物、探索、交易和运输；
- 常规战斗、袭击和 Boss；
- 下界、末地和返回；
- 可恢复建筑与基础红石操作；
- 多人权限、保护拒绝和隐私；
- API、数据库和多 bot 长时间运行。

## OUT_OF_SCOPE

以下内容不属于 1.0 的“普通生存玩家”必选能力：

- 创造模式物品栏、直接复制物品和绕过生存消耗；
- 旁观模式穿墙、旁观传送和附身视角；
- OP/服务器控制台命令、命令方块和管理员直接改世界；
- 依赖漏洞、复制、穿墙或未定义行为的技巧；
- 极限速通的版本漏洞和像素级竞速策略；
- 任意服务器自定义小游戏、数据包脚本和未知模组隐藏机制。

Bot 可以在管理员明确启用的调试模式中使用创造/旁观能力观察测试，但这些入口必须与普通
技能隔离并审计，不能用来完成生存任务。自定义玩法通过 P8 适配 API 后另行进入兼容矩阵。

## 状态更新规则

能力成熟度变化时，同一提交必须：

1. 更新本表；
2. 在 [IMPLEMENTATION_STATUS_CN.md](IMPLEMENTATION_STATUS_CN.md) 记录当前事实；
3. 在 [CHANGELOG.md](../CHANGELOG.md) 写用户可见变化；
4. 链接对应测试或 CI；
5. 如果改变架构边界，新增 ADR。
